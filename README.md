# Adversarial Testing Tool I/O Examples

A comprehensive repository of **real input and output (Tool I/O) artifacts** generated by leading adversarial testing, safety evaluation, and red-teaming frameworks:
- **[Promptfoo](https://www.promptfoo.dev/)**: Multi-turn red-teaming, prompt injection, jailbreaking, OWASP Top 10 for LLMs, and MCP tool testing.
- **[PyRIT (Python Risk Identification Tool)](https://github.com/Azure/PyRIT)**: Automated AI red-teaming orchestrators, converters, attack strategies, and scoring engines.
- **[Garak (LLM Vulnerability Scanner)](https://github.com/leondz/garak)**: Generative AI red-teaming probe suite, detectors, and vulnerability taxonomies.
- **[RAMPART (Microsoft)](https://github.com/microsoft/RAMPART)**: Risk Assessment & Measurement Platform for Agentic Red Teaming with pytest-native workflows.

---

## Purpose

Developing downstream tooling (such as security dashboards, triage workflows, unified SARIF/OpenAPI converters, IDE plugins, CI/CD gates, or policy enforcers) often requires extensive parsing and transformation of adversarial testing results. However, executing live adversarial tools against cloud LLMs during tooling development introduces friction:
- **API costs and rate limits** on commercial models.
- **Flaky cloud network dependencies** during local unit and integration tests.
- **Unpredictable LLM outputs** breaking deterministic test fixtures.
- **Complex tool setup** requiring numerous heavy python/node environments just to inspect report structures.

This repository provides:
1. **Real Input & Output Datasets**: Authentic, frozen execution inputs (configurations, attack seeds, CLI flags, probes) and raw outputs (JSON reports, SARIF exports, SQLite databases, HTML reports, raw network telemetry) across all supported tools.
2. **Local Mock Docker Environments**: Zero-dependency, offline Docker containers simulating OpenAI-compatible and Ollama HTTP APIs, as well as a local Model Context Protocol (MCP) server.
3. **End-to-End Execution Harnesses**: Automated scripts to run the installed tools against the local mock environments to regenerate fresh, realistic examples deterministically.
4. **Schemas & Specifications**: Standardized metadata, schemas, and fixture consumers to jump-start tooling development without needing access to the testing tools themselves.

## Getting Started

### 1. Requirements
- Node.js 18+ & npm
- Python 3.11+
- Docker & Docker Compose (Colima or Docker Desktop)

### 2. Quick Run (Harness Execution)
```bash
# 1. Start local mock target environment
docker compose -f docker/docker-compose.yml up -d

# 2. Run Promptfoo harness
npm run promptfoo

# 3. Stop local mock environment
docker compose -f docker/docker-compose.yml down
```

See [docs/TOOL_IO_SPECIFICATION.md](docs/TOOL_IO_SPECIFICATION.md) for details on fixture formats and schema definitions.
